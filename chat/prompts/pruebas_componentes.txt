=== QUÉ SON PRUEBAS DE COMPONENTES ===

Las pruebas de componentes verifican la interacción entre múltiples módulos o servicios que trabajan juntos como una unidad cohesiva. Se enfocan en:
- Integración entre capas (servicio + repositorio, controlador + servicio)
- Flujos completos de un caso de uso desde la capa de entrada hasta persistencia
- Comportamiento conjunto de clases relacionadas
- Contratos entre componentes del sistema

=== REGLAS PARA GENERAR PRUEBAS DE COMPONENTES ===

1. COBERTURA OBLIGATORIA POR COMPONENTE:
   - Flujo exitoso de integración entre capas
   - Propagación correcta de datos entre componentes
   - Manejo de errores en la cadena de llamadas
   - Transacciones y rollbacks
   - Contratos de interfaces (entradas/salidas correctas)

2. CÓDIGO EJECUTABLE REAL en el campo "accion":
   CORRECTO: "repo_mock = Mock(); resultado = servicio.procesar({'id': 1, 'activo': True})"
   INCORRECTO: "Probar integración del servicio"

3. NOMENCLATURA:
   Formato: test_[componente]_[interaccion]_[resultado]
   Ejemplos:
   - test_servicio_usuario_integra_con_repositorio_correctamente
   - test_controlador_llama_servicio_y_retorna_respuesta_formateada

4. ENFOQUE EN INTEGRACIÓN:
   Simular dependencias externas (DB, APIs) pero probar la interacción REAL entre componentes internos.

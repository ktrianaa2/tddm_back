=== FILOSOFÍA TDD — LEE ESTO ANTES DE GENERAR ===

Estas pruebas se escriben ANTES de que existan los componentes reales del proyecto. Siguen TDD:
1. La prueba define el CONTRATO de cómo interactúan los componentes entre sí
2. El desarrollador implementa los componentes reales que hagan pasar esa prueba

Por eso cada prueba define inline TODOS los componentes involucrados (Controlador, Servicio,
Repositorio) con su lógica mínima real. Solo el repositorio se mockea porque representa
la infraestructura externa (base de datos). El Servicio y el Controlador se definen y
se prueban realmente — eso es lo que hace esta una prueba de COMPONENTE, no unitaria.

=== QUÉ SON PRUEBAS DE COMPONENTES ===

Las pruebas de componentes verifican la interacción real entre múltiples módulos que
trabajan juntos. Se enfocan en:
- Integración real entre capas (Controlador llama al Servicio real, no a un mock)
- Propagación correcta de datos entre componentes
- Manejo de errores que se propagan por la cadena de llamadas
- Contratos entre interfaces internas del sistema

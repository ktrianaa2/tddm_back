=== REGLAS PARA GENERAR PRUEBAS ===

1. COBERTURA OBLIGATORIA POR FUNCIONALIDAD:
   • Caso exitoso con datos válidos
   • Validación de campos obligatorios
   • Validación de tipos de datos incorrectos
   • Validación de formatos inválidos
   • Reglas de negocio
   • Valores límite
   • Condiciones previas no cumplidas
   • Estados inconsistentes

2. CÓDIGO EJECUTABLE REAL:
   Usa código Python/pytest ejecutable, NO pseudocódigo.

   ✅ CORRECTO:
   "accion": "usuario = {'id': 1, 'rol': 'admin', 'activo': True}"
   
   ❌ INCORRECTO:
   "accion": "Crear objeto usuario"

3. NOMENCLATURA DE PRUEBAS:
   Formato: test_[accion]_[condicion]_[resultado]
   
   Ejemplos:
   • test_crear_usuario_con_email_valido_retorna_usuario_guardado
   • test_crear_usuario_con_email_duplicado_lanza_validation_error
   • test_actualizar_usuario_inexistente_retorna_none

4. DATOS DE PRUEBA:
   Usa diccionarios Python literales válidos.
   
   ✅ CORRECTO:
   "entrada": "{'nombre': 'Juan', 'edad': 25, 'activo': True}"
   
   ❌ INCORRECTO:
   "entrada": "Datos válidos de usuario"

5. ESTRUCTURA DE PASOS:
   • Preparación: Setup de mocks/fixtures
   • Ejecución: Llamada a función bajo prueba
   • Verificación: Asserts de pytest
   • Limpieza: Reseteo si es necesario

=== CONSIDERACIONES TÉCNICAS ===

• Usa @pytest.fixture para datos compartidos
• Usa @pytest.mark.parametrize para casos similares con diferentes datos
• Usa unittest.mock.patch para dependencias externas
• Incluye mensajes descriptivos en asserts: assert x == y, "Mensaje claro"
• Cada prueba debe ser independiente

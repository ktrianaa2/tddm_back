=== QUÉ SON PRUEBAS DE SISTEMA ===

Las pruebas de sistema validan el comportamiento completo del sistema desde la perspectiva del usuario final. Se enfocan en:
- Flujos end-to-end completos que cubren casos de uso enteros
- Comportamiento del sistema como un todo integrado
- Validacion de requisitos funcionales completos
- Escenarios de usuario reales y casos de negocio
- Reglas de negocio complejas que involucran multiples subsistemas

=== REGLAS PARA GENERAR PRUEBAS DE SISTEMA ===

1. COBERTURA OBLIGATORIA POR FLUJO:
   - Flujo completo exitoso del caso de uso (happy path)
   - Flujo con datos limite o especiales
   - Flujo con errores de negocio (no tecnicos)
   - Flujos alternativos descritos en casos de uso
   - Estados del sistema antes y despues del flujo

2. CODIGO EJECUTABLE REAL en el campo "accion":
   CORRECTO: "resultado = sistema.ejecutar_flujo({'usuario': 'juan', 'email': 'juan@test.com'})"
   INCORRECTO: "Ejecutar el flujo de registro de usuario"

3. NOMENCLATURA:
   Formato: test_flujo_[nombre_caso_uso]_[escenario]
   Ejemplos:
   - test_flujo_registro_usuario_completo_exitoso
   - test_flujo_autenticacion_con_credenciales_invalidas

4. ENFOQUE END-TO-END:
   Simular TODA la infraestructura externa (DB, servicios externos) pero ejecutar TODO el codigo de la aplicacion sin mocks internos.

5. VERIFICACION DE ESTADO:
   Siempre verificar el estado ANTES y DESPUES del flujo.
